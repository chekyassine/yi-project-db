# CLAUDE.md — YI's Project Database

Context for AI sessions. Read this first; it should let you skip re-deriving the architecture.

## What it is
A single **static HTML app** (`index.html`, self-contained HTML+CSS+JS) that displays ~318 project ideas/tools/methods (originally extracted from Google Keep) with search, filters, and per-card annotations. Live at **https://yi-project-db.pages.dev** (or custom domain).

## Stack & hosting
- **Repo (source of truth):** `github.com/chekyassine/yi-project-db`, branch `main` (public).
- **Hosting:** Cloudflare Pages project `yi-project-db` — **auto-deploys on every push to `main`** (no build command; publish dir = repo root). A push = a live deploy within ~1 min.
- **Database:** Supabase project `yi-project-db` (org `squarepack`), URL `https://xusrtrlwtwtkwmznmahd.supabase.co`. Table `overlay(id text pk, data jsonb)`. RLS on with anon full read/write (intentionally no auth for now). The **anon/publishable key is embedded in `index.html`** (`const SUPA={url,key}` in `<script>`) and is **public by design** — safe. There's a jsonblob fallback + self-heal if `SUPA` is blank.

## Files
- `index.html` — the entire app (~35KB, readable). Was originally generated by a Python builder `build_html.py` that is **not in the repo** — editing `index.html` directly is fine (ask the owner for the generator if needed).
- `data.json` — base catalog: array of `{id,title,category,phase,tags[],summary,from,date,source_note}`. IDs `P001…P318` are base notes — **stable, never renumber** (overlay annotations key off IDs and would detach).
- `supabase.sql` — table/policy setup. `README.md` — brief notes. `CLAUDE.md` — this file.

## Data model (the key idea): content and user-edits are SEPARATE
- **Base** = `data.json` (immutable content; change via git commits only).
- **Overlay** = one JSONB row (`id='main'`) in Supabase:
  ```
  { ann:{ ID:{star,rating,doability,prio,color,arch,trash,tags?} },
    ed:{ ID:{title,summary} },
    add:[ newItems ],
    del:[ IDs ] }
  ```
- The app **merges base+overlay at load** into the live view `DB` (`rebuild()`), and **writes only the overlay**. This keeps user data safe when the catalog changes.

## Code map (functions, not line numbers — lines drift)
- **Config/consts:** `SUPA`, `CATS`, `COL`, `LAB`, `PHASES`, `COLORS`/`CMAP` (color palette), filter state vars `fc,fp,fstar,farch,ftrash,fmin,fdo,fprio,fcolor,ftag,fq`.
- **Store:** `supaGet()/supaPush()` (Supabase), `binURL()/createBin()/pushBin()` (jsonblob fallback), `pullNow()`, `scheduleSync()` (debounced 1s), `saveO()` (localStorage cache + sync). `boot()` loads base then overlay.
- **Merge:** `rebuild()` = BASE minus `del`, apply `ed`, `Object.assign(ann)`, then append `add`. So any overlay field (e.g. `color`) auto-appears as `e.<field>` on cards.
- **Mutators (overlay only):** `setAnn(id,{...})`, `setEdit(id,title,summary)`, `addNote(it)`, `delForever(id)`, `importFull(arr)`.
- **Filters:** `buildStaticChips()` builds chip rows + handlers; `match(e)` decides visibility; `refreshCats()`, `renderTagBar()`.
- **Render:** `cardHTML(e,c)` builds a card; `render()` filters `DB`, groups by category, injects into `#grid`. `grid.onclick` is a **delegated handler** — reads `data-*` attrs (`data-star/arch/trash/rate/do/prio/color/tag/rt/add/edit/del/exp`) and calls the right mutator.
- **New note / export / import:** modal `#nov`; `exp` downloads `DB` as JSON; `impf` → `importFull`.

## Features
Search; filters for category / phase / favorites / archived / trash / interest(★) / doability(★) / priority / **color** / tags. Per-card: heart, two 5-star ratings (interest + doability), priority (low/mid/high), **color (12 predefined swatches + none)**, tags (add/remove, click-to-filter), inline edit, archive, trash, delete-forever. Add-note form. Full Export/Import.
- **Color feature:** `COLORS` = 12 hue-spaced colors tuned for the dark theme. Stored as `ann[ID].color`. Card shows a left stripe (`box-shadow inset`) + subtle `color-mix` wash via `--cc`; also a `#colorf` filter row (Any / 12 / None). Round-trips through export/import.
- **Scroll-hide filter bar:** `.bar` is `position:sticky`; a small rAF scroll listener (just before `boot()`) adds `.bar--hidden` (`translateY(-100%)`) when scrolling **down** past the header and removes it when scrolling **up**. Won't hide while an input in the bar is focused.

## How to make changes
- **Catalog content / bulk edits** (e.g. rename a tag across notes): write a small script over `data.json`, commit → auto-deploys. Never renumber base IDs.
- **App/UI changes:** edit `index.html` directly.
- **New per-note annotation field:** add to the `setAnn` write path + read it as `e.<field>` in `cardHTML` (merge is automatic via `rebuild`), add to `match()` if filterable, and add to the `importFull` copied-keys list so it survives export/import.

## Workflow & verification
- Loop: **edit → `git commit` → `git push origin main` → Cloudflare Pages auto-deploy**. Surface the diff and confirm before pushing anything non-trivial (push = live deploy). Git identity + HTTPS push auth are configured on the maintainer's machine; `gh` CLI is **not** installed.
- **Verify UI changes in a browser before pushing.** Opening `index.html` from disk still runs live (it connects to Supabase and loads real data).
- **Do NOT pollute production data when testing:** clicking a real control calls `setAnn` → syncs to Supabase. To test the render/filter path safely, inject values onto `DB` in the page console and call `render()` (NOT `rebuild()`, which regenerates `DB` from base+overlay and wipes injected values). To test a real click path, stub `pushBin`/`scheduleSync`, snapshot `O`, act, then restore `O` and `rebuild()`.

## Gotchas
- Free Supabase projects **pause after ~1 week of inactivity** (resume in the dashboard). Symptom: app loads but shows no notes / "Offline".
- The anon key is public (fine for now — add auth + tighter RLS to lock down later).
- **Don't renumber base IDs** or overlay annotations detach.
- One invalid CSS value invalidates its whole declaration — keep `color-mix` (or other newer features) in their own property/rule so a fallback survives.
